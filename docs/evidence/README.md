# 验收证据约定

以各任务的原始验收标准为验收范围。某项本地实现通过，不代表对应任务的全部真实实验通过。

每份证据必须包含：日期、Git commit、运行环境及版本、配置和数据路径、实际运行命令、退出码/原始日志位置、结果、明确尚未验证的要求。性能实验另附同条件交替的 baseline/candidate 至少三轮原值、中位数和范围。FP8 的吞吐必须与同一配置的留出精度差同时出现。

证据类型应明确写为以下一种：

- **本地单元测试**：纯函数、解析器或受控命令替身，不能证明真实集群行为。
- **本地集成测试**：真实 CPU/gloo、小模型、gVisor 或 HTTP 流式服务；必须说明运行了哪个实际后端。
- **真实单卡/多机实验**：附硬件、拓扑、实际版本、镜像 digest、模型 revision、调度与现场日志。
- **待验证/未运行**：写明缺少的资源与精确重跑命令，保留原验收条件。

`raw/` 保存可审阅的原始小日志和机器可读记录；大型 trace、checkpoint 和数据集使用外部路径及 SHA256 索引，不把文件名、配置或模拟结果视为真实运行证明。不得写入凭证或模型不可见的隐藏测试答案。

每项审查必须检查计划的 Review Focus：静默降速、policy_version、有界陈旧度、代码奖励作弊、回放客户端滞后，以及 FP8 精度与吞吐成对记录。
